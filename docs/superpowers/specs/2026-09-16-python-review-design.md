## 0. 一页结论

1. **不另起一套课程目录**：知识点从你现有 168 个任务里拆出来，每个知识点记录 `taskRefs`（来自哪些任务），完成任务时按 `taskRefs` 精确生成复习项。
2. **粒度硬规则**：一个知识点 = 能在 5～15 分钟里"回忆 → 对答案 → 自评"，而且**一道代码预测题只能考一个机制**。
3. **规模（按真实任务文本统计）**：168 个任务里的并列机制合计 502 个；补上任务隐含但必需的前置、去掉重复与元任务后，**全 8 周约 500 个知识点 / 约 2500 道题**（±15%）。

5. 第 2～8 周各一批；第 6～7 周（线程/进程/asyncio）属于进阶层，按目标决定做不做。
6. **复习独立于任务完成**：任务只是触发器，掌握程度只由会话里的主动作答决定。

## 1. 粒度准则（硬规则，违反就拆）

- **R1 单一机制**：一道代码预测题只需一个机制就能解释输出。若需要"既是作用域又是闭包"才说得清 → 拆。
- **R2 一次答完**：回忆 + 对答案 + 自评能在 5～15 分钟内完成；超过 15 分钟 → 拆。
- **R3 五类题都能独立写**：概念 / 预测 / 排查 / 编程 / 易错点都能只围绕它写，不必借别的知识点。
- **R4 唯一根因**：答错时能定位到唯一原因，不出现"不知道是作用域错了还是闭包错了"。
- **R5 可一句话命名**：名字里不含"和 / 与 / 以及"。**任务文本里的每个并列连接词都是待拆信号。**

## 2. 从任务得到知识点的规则

- **M1** 任务文本里每个并列机制各取一个候选点。
- **M2** 动词是"解释 / 预测 / 排查 / 口述 / 复盘 / 归类 / 建立"的并列项，通常是**已有知识点的题目形态**，不新开点。
- **M3** 元任务（能力基线诊断、复盘错误假设、建立补漏队列、安排回忆练习）**不产生知识点**，它对应 app 自身功能（薄弱点、补漏队列、复习调度）。

| `predict` | 代码预测题：代码 + 期望输出 + 解释 |
| `debug` | 错误排查题：坏代码 + 根因 + 修法 |
| `code_task` | 实际编程题：需求 + 验收要点 + 参考实现 |
| `pitfalls` | 易错点条目（可多条） |
| `origin` | `builtin`（内置课程库）/ `ai`（AI 生成补充） |

完整示例 `py.mutability.default-arg`：

- 概念题：用自己的话说清"默认参数在**函数定义时**求值一次"，以及它为什么会在多次调用间累积。
- 代码预测题：
  ```python
  def add_item(item, items=[]):
      items.append(item)
      return items
  print(add_item(1)); print(add_item(2)); print(add_item(3, [])); print(add_item(4))
  ```
  先写输出，再解释每行为什么是这个结果（含"第 4 行为什么不是 `[3]`"）。
- 错误排查题：一段用它当"缓存"的代码（第二次调用拿到旧数据），找根因并解释"为什么看起来默认值是空的"。
- 实际编程题：用 `None` 哨兵重写 `add_item`，并写测试证明多次调用互不影响。
- 易错点：可变默认参数 / 调用侧共享同一列表 / 把默认值当"每次新建"。

校验规则（写成自动化校验，失败即拒绝导入）：五类题槽位全部非空、`minutes` 在 5～15、`code` 唯一且形如 `py.<主题>.<点>`、预测题必须有期望输出与解释、编程题必须有验收要点、`taskRefs` 必须指向真实任务 id、`level` 属于三层之一。

## 7. 复习会话与调度

- **会话状态机**：`出题 → 我写（可选）→ 揭示答案/历史 → 5 档自评 → 下一题 → 结束总结`。
- **硬不变量（可自动化断言）**：自评提交前，答案、参考答案要点、历史答案**不得出现在 DOM** 里——这是"主动回忆而不是重读"的机器判据。
- **5 档 → 下次间隔**：完全不会 → 当天/次日（并记一次失误）；看过但说不清 → 1～3 天；基本掌握 → 7 天；可以独立写代码 → 14～30 天；可以讲给别人听 → 30～60 天。间隔随连续答对逐步拉长，答错回退。
- **每日限量**：默认 5～15 项（可在设置里调），**逾期项按到期时间排队、绝不一次全塞**；今日必须复习 / 即将到期 / 已逾期分开显示。
- **筛选**：逾期、项目、标签、题型（概念/预测/排查/编程）、Python 模块、周次、薄弱知识点。
- **AI 判分（可选按钮）**：只在点击时调用，把题目 + 参考答案要点 + 我的答案交给 AI，返回"缺什么/错在哪/补漏建议"；不改变自评档位，只是参考。

## 8. 生成回流

1. **完成任务** → 按 `taskRefs` 取该任务的 3～5 个知识点生成复习项；库里没有的（AI 补充）标 `origin='ai'`。
2. **AI 验收失败** → 生成补漏题挂在同一知识点上，并进"薄弱点"列表。
3. **多次答错**（阈值可配）→ 知识点进"薄弱点"列表，次日优先出现。
4. 第 8 周的综合验收周只出**综合题**（跨知识点的编程题），不新造知识点。

## 10. 验证方案

2. 会话不变量断言：自评前答案不入 DOM（前端脚本测试）。
3. 调度单测：五档 → 间隔映射、每日上限、逾期不全塞、答错回退。
4. 生成回流测试：完成任务 → 恰好 3～5 项且来自 `taskRefs`；验收失败 → 补漏题；多次答错 → 薄弱点。

6. 若复习内容落独立库：备份/恢复/导出必须覆盖该库（往返测试）。
