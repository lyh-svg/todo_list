# Python 复习清单

## 最简单的使用方式

打开 `deepseek.env`，只修改这一行：

```bash
DEEPSEEK_API_KEY=你的_API_Key
```

保存后双击 `open-ai-list.sh`。它会自动启动本地服务并打开：

```text
http://127.0.0.1:8765
```

服务会在每次验收前重新读取 `deepseek.env`，因此以后更换 Key 只需修改并保存该文件，不需要重新启动服务。

页面打开后会每 30 秒向本地服务发送一次心跳。所有清单页面都关闭后，服务连续 5 分钟收不到心跳会自动退出；只要还有一个页面开着，服务就会继续运行。

项目状态现在只由本地 Python 服务保存到 `data/todo.sqlite3`。所有项目、任务、完成状态、AI 验收记录、逐题对话和背景图片共用这一个 SQLite 文件。程序不再读取或写入浏览器 IndexedDB；SQLite 服务未启动时，页面会提示启动服务，不会偷偷切换到另一套项目数据。

数据库文件可以直接复制备份；不要删除或移动 `data/todo.sqlite3`，除非已经完成备份。以后创建新项目或新的 AI 对话时，都会继续写入这个文件，不会生成新的数据库文件。备份列表每一行右侧的删除按钮只删除对应的备份文件，不会影响当前数据库。

如果文件管理器把脚本当作文本打开，可以在终端执行：

```bash
cd /home/xiaoi/downloads/todo-list
./open-ai-list.sh
```

也可以使用前台启动方式：

```bash
./start-ai.sh
```

SQLite 模式下不要直接双击 `index.html`；请使用 `open-ai-list.sh`，它会启动本机 Python 服务并打开页面。服务未启动时，页面不会加载或保存项目数据。

## 长期使用与数据安全

- SQLite 使用 WAL 日志、10 秒忙等待和正常同步级别，适合本机多标签页并发读写。
- 每次保存都带有递增版本号；如果两个页面同时修改，后提交的一方会收到冲突提示，不会静默覆盖另一页的数据。刷新页面后再继续操作。
- 服务启动时会执行 SQLite 快速完整性检查；检查失败时停止启动，避免继续写坏数据。备份只在你点击“创建数据库备份”时生成；恢复操作会额外保留一份恢复前应急备份。
- 所有项目仍共用一个 `todo.sqlite3`，内部使用 `projects`、`nodes`、`assessments`、`conversations` 和 `app_asset` 分表保存。修改一个任务时只更新发生变化的节点和验收记录，不再重写整个项目 JSON。
- 页面启动时检查最大的单个项目。单个项目达到 50 MB 前会在 75%（约 37.5 MB）处提醒；超过 50 MB 才会拒绝该项目的保存。项目总大小不受 50 MB 限制，因此几十或几百个普通项目不会共同挤占这一额度。
- AI HTTP 请求上限仍为 5 MB；本地项目保存接口单独预留 110 MB 传输空间，以容纳转义后的单个 50 MB 项目。
- 项目详情底部的“清理验收记录”按钮可手动清理当前项目的 AI 对话、题目历史和回答草稿；操作前会确认，并保留已有的通过状态、评分和总结，不会自动删除任何记录。
- `/api/storage` 提供只读诊断信息：数据库文件大小（含 WAL 临时文件）、所有项目总大小、最大项目大小、项目数量、版本号和单项目上限。可在浏览器打开 `http://127.0.0.1:8765/api/storage` 查看。
- 数据库没有人为的项目条数上限，实际容量受磁盘空间影响；50 MB 是单个项目重组后的逻辑上限，只用于让单次浏览器传输保持可控。背景图片也在 SQLite 中，因此完整数据库备份会同时包含背景。

数据库升级到分表结构前会保留完整备份。迁移只有在逐项目重组结果与旧 JSON 完全相等后才提交；旧 `project_state` 表随后从主库删除，旧格式仅保留在迁移前备份中。

## 验证与维护

检查数据库完整性和当前表：

```bash
python3 - <<'PY'
import sqlite3

connection = sqlite3.connect('data/todo.sqlite3')
print(connection.execute('PRAGMA quick_check').fetchone()[0])
print([row[0] for row in connection.execute(
    "SELECT name FROM sqlite_master WHERE type='table' ORDER BY name"
)])
PY
```

正常结果包含 `ok`，以及 `projects`、`nodes`、`assessments`、`conversations`、`app_asset` 等表，不应再出现 `project_state`。页面可以创建、重命名、删除和恢复完整数据库备份；重命名只修改备份文件名，不改变其中的数据。普通启动和保存不会自动生成备份；恢复前程序仍会自动生成一份 `before-restore-*.sqlite3` 应急备份。

## 项目级 AI 验收

AI 验收是按项目设置的，不是所有项目的默认要求：

- 新建项目时勾选“启用 AI 验收”，该项目下所有任务都必须经过两阶段验收。
- 不勾选时，这是普通项目，任务可以直接勾选和取消。
- 已有项目可以在详情页右上角切换“AI 验收”。开启后，项目内任务会统一要求验收；关闭后恢复普通清单操作。
- 项目级开关不会影响其他项目。
- Python 主项目底部固定保留“补漏队列”，刷新或新增周后仍会自动保持在最底部；其中的具体补漏任务可以继续新增、编辑和删除。
- 每次重新加载页面时，周和学习单元默认收起，避免列表过长；需要查看内容时再点击三角展开。

默认模型：

- 快速验收：`deepseek-v4-flash`
- 深度验收：`deepseek-v4-pro`

如果 DeepSeek 控制台中的模型 ID 不同，直接修改 `deepseek.env`：

```bash
DEEPSEEK_FLASH_MODEL=实际的_flash_模型_ID
DEEPSEEK_PRO_MODEL=实际的_pro_模型_ID
```

如需使用兼容 DeepSeek Chat Completions 协议的其他地址：

```bash
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

也可以在该文件中用 `DEEPSEEK_API_URL` 指定完整的 `/chat/completions` 地址。系统环境变量优先于配置文件。

## 验收规则

- 内置课程任务需要逐项 AI 验收，不能用父节点批量完成。
- 第一阶段三道题全部通过后，第二阶段可以留空直接提交；填写代码、文字说明或上传文件时，才会继续调用 AI 验收。
- AI 明确判定通过后，任务才会自动完成；页面只显示“通过”，不显示分数。
- 当前题回答和上传的代码会发送到配置的 DeepSeek API。
- API Key 只由本机 Python 进程读取，不会写入网页或返回浏览器。
- AI 请求体上限为 5 MB；单个代码文件仍限制为 512 KB，最多 10 个文件。
- `deepseek.env` 已加入 `.gitignore`，并应保持仅当前用户可读写。
- 本地服务不会执行提交到验收表单中的代码。

## 上传代码和 AI 出题

打开任意任务的 AI 验收窗口后，可以点击“上传代码文件”，选择 PyCharm 中的 `.py`、`.pyw`、`.pyi`、`.txt`、`.md`、`.json` 或 `.toml` 文件。每次最多 10 个文件，单个文件最多 512 KB；文件会以只读文本形式发送给模型，不会被运行。

上传后先点击“重新出三道题”。第一阶段一次只显示一道题，填写结论、预测结果和解释；每道题都是一个独立的短多轮对话。AI 会结合当前题此前的回答和反馈判断：核心理解已经清楚就直接通过，确有关键疑点时只追问当前题的一个细节，你补答后继续判断。当前题通过后自动进入下一题，三题全部通过才进入第二阶段。第二阶段可以留空直接提交，也可以上传你自己写的实现代码，或直接在回答框中写代码；填写内容时 AI 会继续验收。

已经通过的任务可以再次点击复选框取消完成，但这会清除两阶段验收记录，并显示“曾通过 N 次 · 待验收”标记。之后再次完成时，必须重新回答三道题，再提交新的实现内容。
