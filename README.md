# 复习清单（本机运行）

一个只在自己电脑上跑的复习清单：**树形任务（周 → 学习单元 → 任务）+ AI 验收 + 间隔复习**。
数据全部存在本机 SQLite；只有点"AI 验收"时，当前题目和你的回答才会发给 DeepSeek。

---

## 1. 5 分钟跑起来

**环境要求**：Linux / macOS / Windows(WSL) 上的 `python3`（3.10+，开发环境是 3.14）。
没有第三方依赖 —— **不用 `pip install`，也不用建 venv**。

```bash
cd /home/lyh/todo_list
cp deepseek.env.example deepseek.env     # 只需一次
# 编辑 deepseek.env，把 DEEPSEEK_API_KEY 换成自己的 Key
./open-ai-list.sh
```

脚本会启动本地服务并自动打开 `http://127.0.0.1:8765`（地址里带一次性 token）。

- 不想自动开浏览器：`TODO_NO_BROWSER=1 ./open-ai-list.sh`
- 想在前台看日志：`./start-ai.sh`（Ctrl+C 退出）
- 文件管理器把脚本当文本打开时，就在终端里执行 `./open-ai-list.sh`
- **不要直接双击 `index.html`**：项目数据只能通过本地服务读写

## 2. 第一次使用

1. 首页输入项目名 → **新建项目**。
   - 勾选"启用 AI 验收"：该项目下每个任务都必须先通过 AI 验收才能算完成。
   - 勾选"AI 帮我规划"：AI 按你输入的主题自动生成"周 → 学习单元 → 任务"。
2. 进入项目 → 添加周 → 在周下面继续加学习单元和任务（行内按钮：`+` 加子节点、`✎` 改名、`✕` 删除）。
3. 完成任务：
   - **普通任务**：直接勾选复选框。
   - **需要 AI 验收的任务**：点复选框会弹出验收窗口，分两阶段：
     1. AI 根据任务出 3 道题，**一次只答一题**，把核心机制讲清楚才进入下一题；
     2. 三题通过后进入实现阶段：可以**留空直接提交**，也可以上传或粘贴自己的实现代码继续验收。
   - AI 判定通过后任务才自动完成。可以上传 `.py/.txt/.md` 等文件（只读发送给模型，**不会执行**）。
4. 取消勾选已完成的任务会清掉验收记录，并显示"曾通过 N 次"。

## 3. 常用功能

| 功能 | 位置 | 说明 |
| --- | --- | --- |
| AI 验收 | 项目详情右上角"AI 验收"开关 | 项目级开关；开启后该项目的任务必须通过三题验收 |
| 间隔复习 | 项目详情右上角"间隔复习"开关 | 打开后，完成任务会自动排到次日复习；任务行的 ◷ 可手动安排日期 |
| 复习队列 | 首页"今日待复习" | 今天到期 + 逾期；可直接评分（again / hard / good / easy）重排下次复习 |
| 备忘录 | 更多工具 → 打开备忘录 | 独立小本子，支持置顶，可整库导出/导入 |
| 核心摘要 | 验收窗口 / 复习队列的"核心摘要" | 让 AI 用一段话总结该题知识点；同一道题只保留最新一条 |
| 全局搜索 | 首页"全局搜索" | 跨项目搜索项目名和任务文字 |
| 任务元数据 | 任务行的 `⋯` 或点徽标 | 优先级（高/中/低）、截止日期、标签、预计耗时、备注、资料链接，以及周期规则 |
| 今日工作台 | 首页"今日工作台" | 一页看待办：逾期 / 今天到期 / 未来 7 天 / 今天要复习 / 收集箱；行内可完成、延期到明天、归类、打开 |
| 收集箱 | 工作台顶部的输入框 | 一句话先记下来，之后再归类到项目 / 周 / 单元（归类保留全部元数据） |
| 最近 | 首页"最近" | 最近打开、最近修改、最近完成，点一下直接跳过去 |
| 筛选视图 | 项目列表上方 | 把常用筛选（优先级 / 标签 / 截止 / 关键词）存成标签，一键切换 |
| 批量编辑 | 项目详情底部"批量选择" | 勾选多个任务后统一改优先级、增删标签、设/延期截止、完成、移动到其他项目 |
| 归档 | 项目卡片上的 ▣ | 把做完的项目收起来，默认列表不再显示（状态筛选里选"已归档"可查看） |
| 拖拽排序 | 直接拖动任务 / 单元 / 周 | 拖动时行上会出现落点提示（放到前面 / 后面 / 放进这个单元）；跨单元、跨周都行，松手就落库 |
| 移动 / 复制 | 任务行的 ⇄ 与 ⧉ | ⇄ 可以把任务移到别的周/单元甚至别的项目；⧉ 复制节点（可选是否带走子任务、完成状态、AI 历史、复习安排） |
| 撤销 / 重做 | 详情页 ↶ ↷ 或 Ctrl+Z / Ctrl+Shift+Z | 移动、删除、复制、批量修改、清空、导入都能撤销，**保存后与刷新后依然保留最近几步**（存在本机浏览器里） |
| 导入预览 | 更多工具 → 导入 JSON | 先看差异报告（新增/更新/移除多少、重复 ID、AI 历史怎么处理），再选**替换全部 / 合并到现有项目 / 导入为新项目**；执行前自动留快照 |
| 多格式导出 | 更多工具 → 导出 | JSON（可再导入）/ Markdown（带复选框与元数据，适合打印或贴笔记）/ CSV（一行一个节点，Excel 直接打开） |
| 项目模板 | 新建项目区的"从模板创建" / 详情页"存为模板" | 内置「8 周系统复习」「排错四步训练」；也能把现有项目存成模板（只存结构，不带完成状态与 AI 历史） |
| 复制项目 | 详情页"复制项目" | 复制出一个全新项目，可选是否保留完成状态 / AI 验收历史 / 复习安排 |
| 活动历史 | 更多工具 → 活动历史 | 按时间列出"谁在什么时候改了什么"（排序/复制/删除/导入/归档…），可追溯到具体项目 |
| 删除影响面 | 删除任务前 | 先告诉你会影响多少子节点、多少个任务、其中多少已完成、预计耗时合计，并说明会进回收站 |
| 回收站恢复位置 | 更多工具 → 回收站 | 每条都标明"恢复到删除前的位置 / 原位置已不在会进「孤立任务箱」/ 项目已删除无法恢复"；支持单条、批量与整个项目恢复 |

另外：**回收站**（删除的项目和任务可逐条或批量恢复，每条都显示自动清理日期，默认保留 7 天、可在"管理与设置"里改）、**今日聚焦 / 随机复习 / 进度统计**（首页和项目页的快捷按钮）、**自动归档**（可选：把"所有任务都完成、且超过设定天数没动过"的项目自动收起来，收集箱永不归档）。

### 3.1 一句话快速记录（自然语言）

在工作台的输入框里可以直接写：

```text
明天复习 Python 装饰器 #Python !高 30分钟 @Python项目 每天
```

程序会解析出**截止日期、标签、优先级、预计耗时、项目、周期**，并**先弹预览让你确认或修改**再写入；
如果没写任何关键信息，它就是一条纯文本的快速记录，不会弹预览。

支持的写法：`今天/明天/后天/大后天`、`周X / 下周X`、`N天后`、`M月D日`、`MM-DD`、`#标签`、`@项目`、
`!高 / !中 / !低`（或 `!!` `!1`~`!3`）、`30分钟` / `1.5小时`、`每天 / 每个工作日 / 每周X / 每月N日`。

### 3.2 周期任务

在任务详情里设置周期后，**完成时会自动在同位置生成下一次**（日期按规则顺延；设置了 `until` 就到期停止）。
下一次出现会复制优先级、标签、耗时、备注和链接，但不会继承验收记录与复习安排。

### 3.3 提醒

更多工具 → 提醒 → 开启后每分钟检查一次**逾期、今天到期、今天待复习**的任务，弹页内提示，
并在允许的情况下发浏览器通知（同一天同一条只提醒一次）。

⚠️ **提醒只在页面开着时生效**：本机服务没有系统级调度权限，关掉所有页面后就不会再推送；
打开页面后会自动补一次检查。

## 4. 数据、备份与恢复

所有数据都在 `data/` 目录：

| 文件 | 内容 |
| --- | --- |
| `todo.sqlite3` | 项目、任务、完成状态、AI 验收记录、逐题对话、背景图片 |
| `memo.sqlite3` | 备忘录 |
| `summary.sqlite3` | AI 核心摘要 |

- **创建完整备份**：更多工具 → 数据管理 → **创建数据库备份**，生成 `todo-backup-日期.zip`
  （一个文件里包含任务、备忘录、摘要三个库 + 校验清单），放在 `data/backups/`。
- **查看内容**：选中一份备份 → **查看内容**，可以看到生成时间、包含多少项目/节点/备忘录/摘要，
  以及每个文件的校验和是否通过；**校验不通过时不允许恢复**。
- **下载 / 重命名 / 恢复**：选中一份 → **下载**（存到别处）、**重命名** 或 **恢复**。
  恢复前会自动再存一份完整应急备份；恢复失败会自动回滚，成功后页面自动刷新。
- **自动快照**：每天首次启动自动生成一份；导入数据、恢复备份、清空已完成、清空回收站之前也会各存一份。
  保留策略：最近 7 天全部保留 + 30 天内的每日一份 + 90 天内的每周一份，更早的自动删除。
- **导出 / 导入项目数据**：**导出 JSON** 得到 `todo-projects-日期.json`，在别的机器上用 **导入 JSON** 读回；
  导入是整体替换（会覆盖当前所有项目），导入前会自动快照，重复的项目/节点 ID 会被拒绝并指出位置。
- 数据库版本比程序新时，启动会直接拒绝并提示升级（避免降级写坏数据）。
- 不要手动删除或移动 `data/todo.sqlite3`；想直接拷贝这些文件，请先关掉页面、等本地服务退出。

## 5. 配置（DeepSeek）

只需要改 `deepseek.env` 里的 Key：

```ini
DEEPSEEK_API_KEY=sk-你的密钥                          # 必填
DEEPSEEK_FLASH_MODEL=deepseek-v4-flash                # 快速验收用的模型 ID
DEEPSEEK_PRO_MODEL=deepseek-v4-pro                    # 深度验收用的模型 ID
DEEPSEEK_BASE_URL=https://api.deepseek.com            # 官方地址，通常不用改
# DEEPSEEK_API_URL=                                   # 可选：直接指定完整 /chat/completions 地址
```

- 模型 ID 以 DeepSeek 控制台为准，不一致就改上面那两行。
- **保存即生效，不用重启服务**（每次验收前都会重新读这个文件）。
- 系统环境变量优先于该文件；Key 只被本机 Python 进程读取，不会写进网页。
- 建议执行 `chmod 600 deepseek.env`。

## 6. 排错

| 现象 | 处理 |
| --- | --- |
| 页面说服务不可用 / 读不到数据 | 本地服务没启动：在项目目录执行 `./open-ai-list.sh` |
| 提示未配置 `DEEPSEEK_API_KEY` | `deepseek.env` 里的 Key 没填或填错 |
| 想换端口 | `TODO_AI_PORT=9000 ./open-ai-list.sh` |
| 服务"自己没了" | 正常现象：所有页面关闭后 5 分钟收不到心跳会自动退出（`TODO_IDLE_SHUTDOWN_SECONDS` 可调） |
| 服务起不来 | 看日志 `/tmp/todo-list-ai.log` |
| AI 验收报错 | 检查 Key、模型 ID 和网络；也可换 `DEEPSEEK_FLASH_MODEL` 再试 |
| 点复选框弹出验收窗口，不能直接完成 | 该项目开启了 AI 验收：先通过三题验收；不需要就关掉项目页的"AI 验收"开关 |
| 提示"版本冲突，请刷新页面" | 两个标签页同时改了同一个项目：点顶部状态条或提示里的"解决冲突"，逐项选择保留哪一份 |

## 7. 跑测试 / 自检

一条命令跑完全部检查（语法 + 静态检查 + 全量测试 + 端到端 + 行尾约定）：

```bash
./scripts/check.sh            # 全部（含真浏览器与反向验证）；quick 只跑语法+静态+单测+前端冒烟
```

也可以单独跑某一层：

```bash
python3 -m unittest discover -s tests   # 全部用例（后端单测 / HTTP 层 / AI 层 / 前端脚本 / 端到端 / 浏览器）
python3 -m pytest -q                    # 同一批用例，pytest 也能发现（可选 runner）
node tests/frontend/dom-smoke.js        # 前端"真实加载页面并点击"的 68 条运行时断言（含新建/导入预览/恢复/AI/删除撤销/复制）
bash tests/e2e-verify.sh                # 隔离服务端到端 174 项（随机端口 + 临时库）
ruff check . && npx eslint .            # 静态检查
```

测试全部使用临时目录里的数据库，**不会碰 `data/` 下的真实数据**；没装 node 时前端脚本会自动跳过。

### 真浏览器测试（可选）

`tests/test_browser_flows.py` 用 Playwright 驱动真 Chromium 跑"新建项目 → 添加任务 → 刷新 → 导入 JSON → 恢复备份 → AI 规划"。
需要一次性准备：

```bash
./scripts/browser-test.sh          # 一条命令：没系统库时自动本地解包（不需要 sudo）
python3 -m unittest tests.test_browser_flows -v   # 库齐全时也可以直接跑
```

`scripts/browser-test.sh` 会先确认 Chromium 已下载；如果缺 `libnspr4/libnss3`，它把对应的 deb
下载并解包到 `.playwright-libs/`，用 `LD_LIBRARY_PATH` 指过去——**不需要 root，也不改系统目录**。
机器上已有系统库（或你跑过 `sudo python3 -m playwright install-deps chromium`）时会跳过这一步。

没装或浏览器不可用时这些用例会**自动跳过**（`TODO_SKIP_BROWSER=1` 可强制跳过），不影响其它测试；
CI 里有独立的浏览器任务会真正执行它们。

### 反向验证（测试是不是空转）

```bash
python3 scripts/verify-tests-catch.py
```

把 12 条关键修复逐条改回旧行为，确认对应测试**立刻失败**，然后原样还原：
任何一条"改坏了测试还是通过"就说明那条断言不可信，脚本以非 0 退出。
`./scripts/check.sh` 与 CI 都会跑它。

### 持续集成

`.github/workflows/ci.yml`：每次 push / PR 自动跑

1. `checks`：Python/Node 语法检查 → Ruff → ESLint → 全量 unittest（含 HTTP 层与端到端）；
2. `browser`：安装 Playwright + Chromium（含系统依赖）后跑真浏览器流程。
